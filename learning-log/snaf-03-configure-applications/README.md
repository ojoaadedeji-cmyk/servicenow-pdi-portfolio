# SNAF Module 3: Configure Applications for Business

## Overview
Covers configuring lists and forms to meet audience needs, comparing the core environment to Service Operations Workspace, and creating/configuring applications and modules.

## Labs

### Section 3.1: Classic Environment Lists and Filters
**User story:** As an IT Product Owner, a way is needed to identify incidents and inquiries for a new internal product launch, working in the Classic Environment.

**3.1.1: Create Classic List Views**
- Created a new, core list view
- Created a new application and module

### Section 3.2: Form Configuration
**User story:** As the Service Desk Manager, fields need to be added to an existing form so the team can maintain data quality needed to accurately identify and record issues related to the new HHD training device, improving the support the technical training team provides.

**3.2.1: Add a Field to a Form**
- Added a field to a form

### Section 3.3: Advanced Configuration
**User story:** As the administrator, data in choice and reference fields added to an existing form needs to be configured so the team can maintain data quality needed to accurately identify and record HHD-related issues.

**3.3.1: Add Category and Reference Values**
- Created a new Subcategory as a dependent value
- Created new records on a reference table
- Enabled auto-assignment of incidents

## Key Concepts Reinforced
- List views and forms can be tailored to different audiences (IT Product Owner, Service Desk Manager, Administrator) without changing the underlying data model
- Form configuration (fields, choice values, reference values) directly supports data quality, which in turn supports accurate triage and reporting
- Auto-assignment of incidents ties configuration work directly to operational efficiency, not just cosmetic form changes

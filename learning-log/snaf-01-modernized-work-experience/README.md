\# SNAF Module 1: The Modernized Work Experience



\## Overview

Introduces the overall course scenario and provides a functional overview of the ServiceNow Platform, covering IT Service Management, Service Operations Workspace, and Employee Center at a high level before deeper modules build on each one.



\## Course Scenario

Fictitious company: Cloud Dimensions, implementing ServiceNow to support IT and HR.



\*\*IT Context:\*\* The IT department is piloting a new device (Infinity Holographic Handheld Device, "Infinity HHD") for 3D onsite repair instruction videos, supported by the Training Technology team. The IT Product Owner needs a way to track incidents and questions during and after the pilot, in order to:

\- Identify areas for improvement in the HHD training program

\- Build technician FAQs in the knowledge base

\- Create an Infinity service catalog item

\- Provide feedback to the manufacturer

\- Monitor support quality for HHD users



\*\*HR Context:\*\* The HR department wants to explore the HR Case Management application's capabilities and what installing/configuring it would involve.



This scenario is the throughline for labs across the whole course, not just Module 1.



\## Labs



\### 1.2.1: Grant and Verify Access to Applications

\*\*Objective:\*\* Understand how roles control user access to applications and modules.



\*\*Steps Taken:\*\*

1\. Logged in as admin

2\. Navigated to User Administration > Users, opened test user

3\. Assigned role via the Roles related list

4\. Impersonated the user to verify access

5\. Removed the role and reverified access was revoked



\*\*Concept Reinforced:\*\* Roles are additive; access is granted by role membership and can be revoked instantly.



\### 1.3.1: Create Incidents Using Classic Lists and Forms

Created an incident via the classic list/form UI, setting category and priority fields, then confirmed it appeared correctly in the incident list. Reinforces: incident fields drive triage and routing in the classic interface.



\### 1.3.2: Work Incidents Using Service Operations Workspace

Opened and worked an incident from within Service Operations Workspace instead of the classic UI. Reinforces: the same incident data is accessible through multiple interface layers; each suited to a different user type (agent vs. admin).



\### 1.3.3: Check Incident Status Using the Employee Center Portal

Logged in as an end user and checked incident status via the Employee Center self-service portal. Reinforces: Employee Center gives end users visibility into their own requests without needing agent-level access.



\## Key Concepts Reinforced

\- The course scenario (Cloud Dimensions) frames every subsequent module's lab around a realistic IT/HR service delivery problem

\- ServiceNow's platform spans multiple "views" of the same incident data: classic UI, Service Operations Workspace, and the Employee Center self-service portal

\- Access control (roles) is the first gate before any of these views become usable to a given user
